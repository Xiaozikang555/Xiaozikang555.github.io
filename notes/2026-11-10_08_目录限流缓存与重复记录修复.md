# 目录限流缓存与重复记录修复

## 问题一 公共目录 API 限流

初版相册和笔记通过 GitHub 公共 Contents API 获取目录。线上检查出现“访问频繁”提示，影响内容列表。

## 修复方法

改用 GitHub Pages 内置 Jekyll，在构建时遍历 site.static_files 与 site.pages，并生成 collections.json。浏览器直接获取同站 JSON 目录，原始照片与正文仍从 GitHub 原始文件地址获取。发布仓库删除 .nojekyll，允许 Jekyll 处理模板。

## 问题二 旧缓存显示旧界面

提交新 HTML 后，浏览器或静态缓存可能仍持有旧 CSS 和脚本。资源 URL 增加版本参数，使新版页面请求对应资源。版本参数用于更新资源，不会取代 Pages 构建等待。

## 问题三 爱好卡片重复

构建目录合并静态文件与页面时，同一个 Markdown 路径可能重复出现。修复后的 listFiles 使用 Map，以 path 为键去重，再进行筛选和排序。线上已经确认四项爱好各显示一次。

## 问题四 读取失败与浏览器超时

内容请求设置超时并显示错误提示，用户可重新加载。浏览器自动操作本身也可能超时；这种情况不能直接证明网站逻辑失败，也不能当作验证通过，需要保留实际观察结果。

## 相关文件

collections.json、script.js 中的 getCatalog 与 listFiles，以及 index.html 中的资源版本参数。

## 学习要点

静态网站也需要考虑外部服务约束。数据入口应做去重和结构检查，构建与浏览器交互的错误需要分别定位。
